## Threat model (STRIDE)

devkit protects the checks and deploys that every other repository calls. It holds no user data and serves no HTTP app. The thing it can lose is a caller's repository (a token that can push) or a caller's Cloudflare account (a token handed to a deploy step).

Who can call it: any repository that pins a workflow with `workflow_call`, plus anyone who runs the bins. `ci.yml` runs on `pull_request` and on a push to `main`. `code-map-self.yml` runs on a push to `main` and on `workflow_dispatch`.

Entry points:

- Reusable workflows (`workflow_call` only): `ai-author.yml`, `bump-consumers.yml`, `code-map.yml`, `no-bloat.yml`, `pr-footer.yml`, `worker-deploy.yml`, `worker-size.yml`.
- This repo's own workflows: `ci.yml`, `code-map-self.yml`.
- CLIs: `devkit-check-trailers`, `devkit-no-bloat`, `devkit-worker-size`.
- Test helpers exported as `@dustinedwards/devkit/github`, `/network`, `/d1`, `/access`.
- No HTTP route, MCP tool, cron, queue, or webhook.

Where trust changes:

- Caller inputs (`install`, `coverage-command`, `mutation-command`, `pre-deploy`, `verify`, `prepare`) are the caller's own workflow text. They are passed through the environment into `bash -c`. That is the caller's code running in the caller's job. It becomes a problem where the job's token is wider than the step that was supposed to hold it (DK-1).
- Caller secrets arrive only on the steps that map them.
- The code-map job fetches `refs/heads/code-map` with no token, then force-pushes a new tree. A failed read is treated as "there was nothing" (DK-5).
- Pull request descriptions are untrusted text. `pr-footer.yml` edits them with `pull-requests: write`, skips forks, and skips `synchronize`.
- `ai-author.yml` reads the caller's `package.json` and runs `npx` of that spec with `contents: read` and no secret. Same trust as the rest of that repo's CI.

Spoofing: the trailer check is the control on AI author identity. It fails closed when git cannot read the range, and it exits 0 for every event it does not recognise (DK-6).
Tampering: `main` has no branch protection (DK-2). The code-map publish replaces the whole branch. `resetDb` can delete a real table whose name shares an FTS prefix (DK-4).
Repudiation: the map publish commits as `github-actions[bot]`. Actions logs are the only record.
Information disclosure: `GITHUB_TOKEN` is in the environment of every step, including steps that run caller commands (DK-1). The published `code-map.json` is public on purpose.
Denial of service: every job sets `timeout-minutes`. Include and mutation globs are unquoted on purpose so a caller can pass a list. A huge tree in `bump-consumers` is bounded by the GitHub tree API, and a truncated tree is not detected (DK-12).
Elevation of privilege: `contents: write` covers the measure steps, not only the publish step (DK-1). A caller that triggers `worker-deploy` on `pull_request_target` deploys (DK-6).

## Findings

### DK-1 MAJOR, security / CI, confirmed by reading

File: `.github/workflows/code-map.yml` lines 99-100, 111-126, and 529-544. The same shape is in `.github/workflows/code-map-self.yml` lines 22-28, which passes the test suite as `coverage-command`.

The `map` job sets `contents: write` for the whole job. Install, Measure coverage, and Measure mutation run the caller's commands with `bash -c "$INSTALL"`, `bash -c "$COVERAGE"`, and `bash -c "$MUTATION"`. `persist-credentials: false` stops checkout from storing a credential in `.git`. It does not remove `GITHUB_TOKEN` from the step environment. GitHub injects that token into every step, and the job permission applies to every step. The publish step is the only one that names `github.token` in the YAML. The test that claims "only the publish step holds it" (`test/code-map-workflow.test.mjs` lines 36-41) greps the YAML for `github.token` and `secrets.` and stays green.

Path: a caller that runs `npm ci` or the test suite inside this job gives that command a token that can push. `main` is unprotected (DK-2), so a dependency install script or a test can push to `main`. This was not executed on a live runner. The confidence is the workflow plus GitHub's documented default environment.

Smallest fix: two jobs. Measure with `contents: read`. Publish with `contents: write`, taking the JSON from an artifact.

Caller-authored text that the caller passes through the environment into `bash -c` is that caller's own workflow. That pattern is not filed as command injection. `ai-author.yml` runs `npx` of the spec in the checked-out `package.json` with `contents: read` and no secret. That is the same trust as the rest of that repo's CI, and it is not a finding.

### DK-2 MAJOR, supply chain / config, confirmed via the API

`main` is not protected (HTTP 404). Rulesets are empty. Secret scanning and push protection are on. Dependabot security updates are off.

`default.json` is the portfolio Renovate policy. It turns on automerge for the weekly minor/patch group, pins, lockfile maintenance, and vulnerability alerts (`minimumReleaseAge` null on that block, lines 45-55). Dustin's own packages (`DrDustinEdwards/**`, `@dustinedwards/**`, `enarratio`) open at once and automerge on minor and patch (lines 159-185). `platformAutomerge` is true (line 32). Platform automerge does not engage on GitHub without branch protection. Whether any merge has actually landed was not checked. The file's claim that no consumer has branch protection matches this repository. It was not re-checked on the named consumers `dustinedwards-info`, `dustinedwards-mcp`, and `capsid-mcp`.

Smallest fix: protect `main` (require the `ci` check, block force-push). Then `platformAutomerge` has a branch it can merge into, and a stolen `contents: write` token cannot push straight to `main`.

License null and `"license": "UNLICENSED"` are intentional for a private package in a public repo. Noted, not numbered.

### DK-3 MAJOR, correctness / CI, confirmed by reading and by the test that locks it in

File: `bin/no-bloat.mjs`. The header (lines 4-5) says a tool that cannot run is a warning, "never a silent pass". `measure` pushes a warning and continues when knip or jscpd throws (lines 63 and 77). `main` prints the warnings and exits 0 whenever `errors` is empty (line 232). `test/no-bloat.test.mjs` names this: "a tool that fails is a warning and exit 0".

`compare` (line 88) says a finding with no baseline is a row and never an error. A missing `.no-bloat.json` therefore exits 0 with a full set of findings. A jscpd percentage can rise while the clone count stays put: only `clones` is compared (lines 124-126), so the percentage column is display-only.

Path: a caller whose knip or jscpd binary crashes, or who has not committed a baseline yet, gets a green check. `--write-baseline` does refuse to record a partial baseline (lines 208-211). That path is the one that fails closed.

Smallest fix: exit 1 when any tool throws, and exit 1 when there is no baseline. Compare the jscpd percentage the same way as the clone count.

### DK-4 MAJOR, data integrity / tests, confirmed by running

File: `testing/d1.mjs` line 24. `isShadow` is `name.startsWith(`${v}_`)` for every virtual table `v`.

Repro, against the helper as shipped: an FTS table `pages` plus a real table `pages_revisions` with one row. `resetDb` returned `['pages']`. `pages` count 0. `pages_revisions` count 1. The real table was skipped because its name starts with `pages_`.

Path: any test database that has both an FTS table and a real table named `<fts>_<something>`. The real rows survive a reset and leak into the next case. The suite's own FTS test uses shadow names and does not include a real table with that prefix, so the suite stays green.

Smallest fix: skip only the real FTS5 shadow suffixes `_data`, `_idx`, `_content`, `_docsize`, and `_config`.

### DK-5 MINOR, data integrity, confirmed by reading

File: `.github/workflows/code-map.yml` lines 137-148 and 529-544.

"Read the kept mutation run" fetches the `code-map` branch with no credential. Any failure of `git fetch` or `git cat-file` takes the else branch and prints "No kept mutation run". The publish step then `git init`s a fresh tree and force-pushes it. If `mutation.json` was on the branch and this run could not read it, the force-push deletes it.

Path: a transient failure, or a private repo that starts calling this workflow (the comment says only a public repo calls it), drops the kept mutation report. The next maps mark every function stale or carry no mutation numbers. Exit of the step is still 0.

Smallest fix: if the branch exists and `mutation.json` cannot be read, fail the job. Do not publish a tree that omits a file the branch already has.

### DK-6 MINOR, security, confirmed by reading

Two holes, one fix each.

`.github/workflows/worker-deploy.yml` lines 87 and 139 exclude `pull_request` only. A caller that triggers the workflow on `pull_request_target` deploys. Checkout for that event is the base SHA. The Cloudflare secrets are in the deploy step's environment whenever the caller passed them.

`bin/check-trailers.mjs` `rangeFromEvent` (lines 93-105) returns null for every event other than `pull_request` and `push`. `main` then prints "adds no commits" and returns, which is exit 0 (lines 149-151). The header of `ai-author.yml` says a schedule or a dispatch adds no commits. `pull_request_target` is a commit-bearing event, and a caller who points the trailer check at it gets a green check that read nothing.

Smallest fix: exclude `pull_request_target` in both `if`s of the deploy workflow. In `rangeFromEvent`, accept only the two events the header documents, and exit 2 for anything else.

### DK-7 MINOR, tests / security, confirmed by running `callerProblems`

File: `scripts/check-callers.mjs` lines 15, 31, and 35.

The pin rule is `uses:` plus `owner/devkit/.github/workflows/<file>@<ref>` with `ref` matching `^[0-9a-f]{40}$`. Bare `secrets: inherit` is refused.

Three inputs the regex does not see, each run this audit:

- A file with one good call plus a quoted `uses: "...@main"` returns `[]`. The quote stops the match, and one good call keeps the "no call" error from firing.
- `secrets: "inherit"` returns `[]`.
- Forty zeros, which is what `examples/*.yml` pin and what CI checks with `node scripts/check-callers.mjs examples/*.yml`, returns `[]`. The all-zero sha matches the character rule and names no commit.

`check-callers` runs on this repo's examples. It does not run inside a caller's repository unless that caller invokes it.

Smallest fix: reject the all-zero sha. Strip one layer of quotes before matching `uses` and `secrets`.

### DK-8 MINOR, tests, confirmed by running the stub

File: `testing/github.mjs`.

- Directory listing (lines 98-109). Seeding `src/a.ts` and `src/sub/b.ts` and listing `src` returns names `a.ts:file, sub/b.ts:file`. The nested file is flattened into the parent listing. GitHub returns a directory entry for `sub`.
- `versionOf` (line 207) hashes `files.get(path) ?? ""`. A missing path returns the empty-blob sha `e69de29bb2d1d6434b8b29ae775ad8c2e48c5391`.
- `GET /git/commits/` (line 71) returns the current tree for any sha.
- The stub does not look at `Authorization`. A tree is applied only when the ref is patched. An unknown host or route throws, which is what the header promises. Blob shas are real `git hash-object` shas and the tests check them.

Path: a test of a directory walk, of "file missing", or of "this commit's tree" can pass against the stub and fail against GitHub.

Smallest fix: list only immediate children, return a 404 sha from `versionOf` when the path is absent, and key the commit route on the sha.

### DK-9 MINOR, tests / portability, confirmed by `npm test` on Windows

CI on this commit is green on `ubuntu-latest`. The local run (Windows, Node v24.21.0) is red for two reasons. This is a gap in local verification, and it is a product bug for anyone who runs the suite on Windows.

- `test/code-map.test.mjs` "coverage lands on the innermost function" expected `0.5` and got `null`. `scripts/code-map.mjs` line 187 keys lcov by `resolve()`, which uses backslashes on Windows. Line 254 looks up `coverage?.[abs] ?? coverage?.[path]`, and TypeScript's `fileNames` use forward slashes. The two strings differ by the separator, so the lookup misses.
- `test/worker-deploy-workflow.test.mjs` run-cases call `spawnSync("mkdir", ["-p", bin])`. On Windows `mkdir` is a shell builtin, the directory is not created, and the following write of the curl stub throws `ENOENT`. Those tests are not skipped on `win32`. The text-only worker-deploy tests passed. `test/no-bloat.test.mjs` and `test/worker-size.test.mjs` already skip their end-to-end cases on `win32`.

Smallest fix: normalise separators in the coverage lookup. Skip the bash run-cases on `win32`, or create the directory with `fs.mkdirSync`.

### DK-10 MINOR, supply chain, confirmed by reading and `npm view`

`bin/no-bloat.mjs` line 28 defaults to `knip@6` and `jscpd@4` through npx when the caller has not installed them. `bin/worker-size.mjs` line 56 defaults to `wrangler@4`. Those float.

`worker-deploy.yml` pins `WRANGLER_VERSION` to `4.107.0`. Current wrangler at the time of this audit is `4.151.3`, 44 releases ahead. No advisory was searched: wrangler is a version string in YAML here, not an installed package. Treat it as a stale pin.

`typescript` `5.9.3` against current `7.0.2` is a devDependency used to parse fixtures. `npm audit` reports 0 vulnerabilities.

Smallest fix: pin the three npx specs to a full version the way the deploy workflow pins wrangler, and bump the deploy pin on purpose.

### DK-11 MINOR, supply chain / config, confirmed

`renovate.json` extends `local>DrDustinEdwards/renovate-config`. `gh repo view` of that name returns the repo named `devkit`. The rename redirect still resolves. A later rename, or a real `renovate-config` repo, would silently change the policy.

Smallest fix: point `extends` at `local>DrDustinEdwards/devkit`.

### DK-12 MINOR, reliability, confirmed by reading

File: `.github/workflows/bump-consumers.yml` lines 76-82 and 102-107.

`readJson` returns null on any error, so a manifest that exists and is not JSON is treated as "not a consumer". `git.getTree` with `recursive: "true"` can set `truncated`. The flag is not read. A consumer whose tree was truncated, and whose `package.json` sat past the cut, is not ticked.

The size of consumer trees was not measured. The omission is what was confirmed.

Smallest fix: fail the repo when `truncated` is true, and treat invalid JSON as a warning that names the path.

## Area by area

### 1. Security

Credential table:

| Credential | Where it lives | Who can read it | What a leak opens | Rotation |
| --- | --- | --- | --- | --- |
| `GITHUB_TOKEN` | Injected into every step | That step's commands | Whatever the job's `permissions` grant. `contents: write` on the code-map job (DK-1). `pull-requests: write` on the footer job. | GitHub issues a new token per job. |
| `CLOUDFLARE_API_TOKEN` | Caller secret, required by `worker-deploy` | Pre-deploy, deploy, and rollback only | The Cloudflare account the token is scoped to | The caller rotates the secret. |
| `CLOUDFLARE_ACCOUNT_ID` | Same three steps | Those steps | The account id, useful together with the token | The caller. |
| `RENOVATE_TRIGGER_TOKEN` | Caller secret `token` on `bump-consumers` | The trigger job | Contents read, Issues read and write, Metadata read, on every repo the fine-grained token can see. It ticks one checkbox. | The caller rotates the PAT. |

No credential is committed. History search found no token prefix and no private key.

Checked and clean, apart from DK-1, DK-6, and DK-7:

- Injection. Caller text goes in through `env`, then `bash -c "$VAR"`. It is not spliced with `${{ }}` inside the script. Workflow `github.event` fields used in `env` (`PR_NUMBER`, shas, event name) are passed as data.
- Validation. Rollback shas must match `^[0-9a-f]{7,40}$` after lowercasing. An unknown sha in the trailer check exits 2. A no-bloat config that is not JSON exits 1. Worker-size fails closed on a missing budget, bad JSON, a failed dry run, or no Total Upload line.
- API and file surface. No HTTP API. The footer script writes pull request bodies and caps the strip at four passes. Publish writes two JSON files on an orphan branch.
- Authentication and sessions. No user auth. The access test helper signs a real RS256 JWT and the test verifies it against the JWKS. The token endpoint does not require PKCE, because it is a stub of the test IdP, and unknown URLs throw.
- Authorization. Job permissions are listed on every workflow. Top level is `contents: read`, or `{}` for bump-consumers. `secrets: inherit` is refused in the unquoted form. Cloudflare secrets are not on the verify step.
- JWT, OAuth, crypto, CSRF, replay, rate limits, SSRF, CORS, CSP. No production use. The rollback guard treats a same-attempt unreadable health check as "roll back", and a different attempt as "do not". Prefix equality of abbreviated shas is intentional and tested. Exit 1 rolls back. Exit 3 does not.
- Headers. No server. The live file's headers are in area 19.

### 3. Secrets and privacy

No secret in the tree or in the history search above. No personal data. The package collects nothing. Privacy claims in the README match that. CI logs the deploy sha and the worker name, not the Cloudflare token (the token is an env var on three steps, not echoed).

### 4. Data integrity

DK-4 and DK-5. Also checked:

- `resetDb` deletes in one batch with `PRAGMA defer_foreign_keys`, quotes identifiers, and never clears `sqlite_*`, `_cf_*`, or `d1_migrations`.
- The rollback guard refuses to roll back a different attempt, and the workflow stores `github.run_attempt` so a rerun of the live gate alone can tell itself from the attempt that shipped. The README states that D1 and KV are not undone by a Worker rollback.
- The map publish is one commit of a fresh tree. A crash before the push leaves the previous branch as it was. A crash after a push that omitted `mutation.json` is DK-5.
- No migration framework lives here. No backup of a database lives here.

### 5. Correctness

DK-3, DK-4, DK-8, DK-9. Also checked and behaving as documented:

- A new branch (`before` all zeros) checks the tip commit only. Tested.
- Author identity is checked on `pull_request` and not on `push`. Tested.
- A 7-character sha prefix matches a full sha in the rollback guard. Tested, and the regex allows 7 to 40 hex digits on purpose.
- Coverage of zero statements in a file that was in the report is treated as coverage 1. That keeps an empty module from looking uncovered.
- `functionsOf` counts `if`, loops, `case`, `catch`, `?:`, `&&`, `||`, and `??`. A comparison used as a value does not add complexity. That matches a control-flow count.
- The three inlined scripts are byte-checked against `scripts/`. A drift fails CI.

### 6. Reliability

DK-12. Also checked:

- Every job sets a timeout. The live gate's 15 minutes sits above 40 polls of 3 seconds plus the rollback's 20 reads.
- Deploy concurrency is the caller's, and the example sets `cancel-in-progress: false`.
- Code-map concurrency group `code-map` does not cancel an in-flight run, so an older map cannot be cancelled into a newer one out of order. Two pushes can still race on the force-push. The later push to finish wins, which can be the older sha. Low risk on a repo this size. Not filed on its own.
- `worker-size` and the deploy fail when wrangler fails. `no-bloat` does not (DK-3).
- No retry loop of its own. The live gate polls a fixed number of times and then fails.

### 7. Performance and cost

No production D1 query, so no `EXPLAIN QUERY PLAN`.

One code-map run is one checkout, one node process, and a force-push of a few dozen kilobytes. The published map for this commit is 29140 bytes. One deploy is one `wrangler deploy` plus up to 40 health reads and, on refusal, one rollback plus 20 reads. One bump-consumers run lists the owner's repos and one tree per repo. The cost is GitHub API calls, bounded by pagination, with the truncated-tree hole in DK-12. No bundle of this repo's own. The Worker size budget is the caller's `.worker-size.json`.

### 8. Compatibility

The package is consumed by git tag (`github:DrDustinEdwards/devkit#v0.7.0` in the README). Exports and bins are listed in `package.json`. `.d.mts` files sit beside the helpers. There is no typecheck script, so a drift between the JSDoc and the declarations would not fail CI (area 9).

Workflow inputs have defaults. A caller pinned to this sha keeps this behaviour. The changelog records 0.7.0 as the worker-size, no-bloat, and code-map release. No schema is stored. The code-map JSON `version` is 1, and the live file matches this commit's sha.

Removing the copy inside the workflow would break the one-sha design, because a caller that pins a workflow sha must run that commit's script without installing the package. Removing the `scripts/` side would break the byte-equality test and the local bin. Other removable comment or wrapper is under about 3%, and removing it would change wording in the job summary more than behaviour.

Grade: B. The three changes that would raise it most: split `codeMap`, split `stubGitHub`, and typecheck the declarations so they cannot drift from the implementation.

### 10. Architecture and simplicity

Real structure: a public git repo. Callers pin a workflow sha. Workflows that must run without an install inline their script. Workflows that run a bin install the caller's own devDependency and call `node_modules/.bin`. `default.json` is data, extended by each repo's `renovate.json`. `testing/` is a library. There is no service, no database, no diagram in the README, and the README's list of workflows matches the files.

Coupling: callers depend on step names and `::error::` sentences in the live gate, because capsid's watcher matches them. The test locks those strings. That is a real contract, and it is tested.

Over-engineering: the inlined copies cost 512 lines and a generator script. They buy a caller that pins one sha and installs nothing. I would keep them. I would not add another generator.

Under-engineering: branch protection (DK-2), the no-bloat exit code (DK-3), and a typecheck.

Shared-package fit: this is the shared package. The Renovate policy living here is right. Nothing in this repo should move out. The GitHub stub's gaps (DK-8) are the sort of thing every consumer inherits.

### 15. CI and deploy

`ci.yml` runs the suite, `check-callers` on `examples/*.yml`, and the trailer bin, with `contents: read` and `persist-credentials: false`. It uses `.nvmrc`. It does not typecheck, lint, or run `npm audit`.

`code-map-self.yml` grants `contents: write` and runs the suite as the coverage command (DK-1).

Deploy is `worker-deploy.yml`: checkout, install, pre-deploy, `wrangler deploy`, then the live gate. The gate polls `/health` until `sha` is this commit, runs the verify command, and rolls back only on exit 1 when the guard agrees. The example caller matches that shape (push to the default branch, concurrency that does not cancel, secrets by name, a full sha of zeros as a placeholder). The placeholder is accepted by the pin check (DK-7).

A caller can ship a Worker with a green `ci` here and a green deploy there while `main` on both sides is unprotected. That gap is DK-2.

### 16. Operations

The live gate is a real health check: it reads JSON `sha` and can refuse. Exit 0, exit 1, and exit 3 are different outcomes, and the watcher strings are tested.
